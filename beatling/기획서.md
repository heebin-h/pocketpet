## 1. 정의와 목표

**한 줄 정의:** 음악을 먹고 자라는 펫이 사는 MP3 플레이어. 무엇을·얼마나·어떻게 듣느냐로 펫의 상태와 진화가 결정된다.

**Rev A 목표:** 컨셉의 핵심 재미(먹이→반응→진화→공유)를 **실물 탁상형 기기 1대에서 14일간 끊김 없이 체험**할 수 있게 만든다. 이 기기로 컨셉 문서의 검증 V2(플레이 루프)·V3(기술)을 수행한다.

**성공 기준 (Rev A 종료 조건)**

| # | 기준 | 측정 |
|---|---|---|
| G1 | 14일 진화 사이클을 실제 시간으로 1회 완주 (시간 가속 시뮬레이션 + 실시간 1회) | 진화 로그 |
| G2 | 7일 무인 연속 운용 중 펫 상태 손실 0 | 운용 로그 (`journalctl`, events 테이블) |
| G3 | 정전 100회 후 상태·청취 로그 손상 0 | HW 개발계획서 §9 T8 |
| G4 | 입력→화면 반응 체감 지연 없음 (목표 <100ms, 미검증) | 로직 분석기 or 고속 촬영 |
| G5 | 테스트 사용자 3명이 설명 없이 30분 내 "밥 주기·다이얼·공유" 수행 | 관찰 |

## 3. 사용자와 핵심 시나리오

**1차 사용자 (Rev A 테스트 대상):** 로컬 음원 라이브러리를 가진 20~30대 — MP3 회귀층, 음악 취향 공유를 즐기는 사람. (수요 규모는 컨셉 V1에서 검증 — 미확인)

**S1. 첫 만남 (Day 0)**
1. USB 메모리 꽂고 전원 → 부팅 후 화면에 알이 나타남.
2. 기기가 라이브러리 스캔(진행률 표시).
3. 아무 곡이나 3곡 끝까지 들으면 알이 부화 → 아기 펫.

**S2. 일상 루프 (매일)**
1. 펫이 단어 소리로 조름 ("배고파" + LED 느린 점멸).
2. 사용자가 [밥] 버튼 → 다음 곡 재생 = 먹이.
3. 끝까지 들으면 펫 냠냠, 30초 안에 넘기면 "퉤".
4. 다이얼 2번 → 펫이 먹고 싶은 맛의 곡 추천.

**S3. 진화와 공유 (Day 3/7/14)**
1. 진화일 아침 LED 빠른 점멸 3회 → 화면에 진화 연출.
2. 다이얼 1번 → 상태/식단 그래프 → [엔코더 길게] → QR 표시.
3. 폰으로 찍어 취향 카드 웹페이지 → SNS 공유.

**S4. 방치와 귀환**
1. 72시간 배고픔 상태 → 펫 가출(화면에 쪽지만 남음).
2. 펫의 최애곡을 끝까지 틀면 귀환 연출.

## 5. 펫 시스템 명세

모든 수치는 **제안값**이며 `/etc/beatling/balance.yaml`로 분리한다(하드코딩 금지). Rev A 운용 중 튜닝한다.

### 5.1 상태값 (0~100, 내부 실수·표시 정수)

| 상태 | 감소 규칙 | 의미 |
|---|---|---|
| 배부름 (fullness) | tick(1분)마다 −0.07 → **24시간 무청취 시 100→0** | 0이면 "배고픔" |
| 기분 (mood) | 자연 감소 없음, 이벤트로만 변동 | 30 미만이면 "삐짐" 애니메이션 |
| 기력 (energy) | 낮 동안 유지, 00~05시 청취 시 다음날 상한 70 | 수면 패턴 풍자 |

### 5.2 먹이 판정 (청취 1회 단위)

| 판정 | 조건 | 효과 |
|---|---|---|
| 완청 | 재생 시간 ≥ 곡 길이의 90% | 배부름 +8, 기분 +2 |
| 부분 | 30초 ≤ 재생 < 90% | 배부름 +3 |
| 스킵 | 재생 < 30초 | 기분 −5, "퉤" 연출 |
| 최애 간식 | 같은 곡 당일 2~3회째 완청 | 기분 +3 추가 |
| 편식 | 같은 곡 당일 4회째 이상 | 기분 −2, "또?" 연출 |
| 과식 | 배부름 100에서 완청 | 효과 없음, "배불러" 연출 |

- 일시정지 시간은 재생 시간에 포함하지 않는다(mpd 상태 이벤트 기준).
- 식단 벡터(§5.3)에는 **완청·부분 청취 시간**만 가중 반영, 스킵은 미반영.

### 5.3 진화

**단계**

| 단계 | 진입 조건 | 형태 수 |
|---|---|---|
| 알 | 최초 부팅 | 1 |
| 아기 | 완청 3곡 | 1 |
| 유년 | 부화 후 3일 | 2 (식단 에너지 축 상/하) |
| 청소년 | 7일 | 4 (에너지 × 밝기) |
| 성체 | 14일 | **5** (아래 표) |

**맛 벡터 정규화 (곡마다, 절대 기준 — D3)**

| 축 | 원값 | 정규화 (0~1, 범위 밖 clamp) |
|---|---|---|
| 템포 | BPM | (BPM − 60) / 120 |
| 에너지 | RMS (dBFS) | (dBFS + 30) / 24 |
| 밝기 | spectral centroid (Hz) | log10(Hz/500) / log10(4000/500) |

**식단 벡터** = 청취 시간 가중 평균. **분산** = 가중 표준편차의 3축 평균.

**성체 결정**: 분산 > 0.25 이면 **잡식(레어)**, 아니면 아래 원형 중 유클리드 거리 최소.

| 성체 | 원형 (템포, 에너지, 밝기) | 대표 장르 (예시) |
|---|---|---|
| 불꽃형 | (0.8, 0.8, 0.5) | EDM·록·댄스 |
| 이불형 | (0.2, 0.2, 0.4) | 발라드·로파이 |
| 반짝형 | (0.5, 0.6, 0.8) | 팝·시티팝 |
| 그림자형 | (0.5, 0.8, 0.2) | 힙합·메탈 |
| 잡식형 | — (분산 기준) | 고르게 듣는 사람 |

- 정규화 범위·원형·분산 임계값은 V3에서 **실제 라이브러리 3개 이상**의 분포를 보고 조정 (현재값은 근거 없는 초기값).
- 장르 오분류 리스크는 컨셉 문서 §5 단점 2와 동일 — 튜닝 실패 시 축 추가(예: 조성) 검토.

### 5.4 펫의 요구 (말하기 버튼)

| 단어 | 발생 조건 | 기대 응답 | 응답 시 |
|---|---|---|---|
| "배고파" | 배부름 < 30, 최대 2시간 1회 | [밥] | 기분 +2 |
| "신나는 거" | 기분 < 50 & 최근 1시간 식단 에너지 < 0.4 | 에너지 ≥ 0.6 곡 완청 | 기분 +5 |
| "조용한 거" | 22시 이후 & 에너지 ≥ 0.6 곡 연속 3곡 | 에너지 ≤ 0.4 곡 완청 | 기분 +5 |
| "놀자" | 2시간 무조작 & 배부름 ≥ 50 | [놀자] | 기분 +3 |
| "잘래" | 기력 < 30 | [재워] | 다음 tick 기력 회복 2배 |

- 무응답 30분 → 요구 소멸, 기분 −1. 모든 요구·응답은 로그(F-RANK 원천).
- 야간(00~07시)에는 소리 없이 LED만 (D9와 별개, 고정 정책).

### 5.5 가출·귀환

- **가출**: 배부름 0 상태가 연속 72시간.
- **귀환**: 가출 중 "최애곡"(누적 완청 시간 1위)을 완청. 귀환 시 배부름 50, 기분 30.
- **사망 없음** (D4). 가출 중 진화 시계는 정지.

### 5.6 시간

- 기준 시각 = RTC(DS3231). 부팅 시 RTC → 시스템 시각, NTP 가능 시 NTP 우선.
- 펫 경과 시간 = `now − last_saved_at`. **음수(역행) 또는 +48시간 초과 점프**면 경과 0으로 처리하고 "어지러움" 연출 + 이벤트 로그 (D8).
- 장기 전원 OFF(정상): 꺼져 있던 시간은 배부름 감소에 **최대 24시간까지만** 반영 (켤 때마다 가출하는 것 방지 — 제안값).

### 6.2 화면 (OLED 128×64, 1bit)

```
 ┌──────────┐ 엔코더 클릭  ┌──────────┐  번호 확정   ┌──────────────┐
 │  HOME    │────────────►│  DIAL    │────────────►│ 서비스 화면     │
 │ 펫 + 아이콘│◄────────────│ 0~9 회전  │◄────────────│ 1 상태 / 2 추천 │
 └────┬─────┘  길게(뒤로)   └──────────┘   길게(뒤로)   │ 3 사서함 / 4 라디오│
      │ 재생 시작 3초 후                                 │ 7 운세 / 0 비밀  │
 ┌────▼─────┐                                         └──────┬───────┘
 │  NOW     │ 곡명 스크롤 + 진행바 + 펫 미니                  │ 1 상태에서 엔코더 길게

                                                       │  QR 카드      │
                                                       └──────────────┘
```

- HOME 상단 아이콘: 배부름·기분·기력 3칸 게이지, 요구 있으면 말풍선.
- 이벤트 화면(부화·진화·가출·귀환)은 전체 화면 연출 후 HOME 복귀.

### 6.4 LED · 소리

| LED 패턴 | 의미 |
|---|---|
| 꺼짐 | 평상 / 가출 중 |
| 느린 점멸 (1Hz) | 펫 요구 대기 중 |
| 빠른 점멸 3회 | 진화·부화·귀환 이벤트 |
| 상시 점등 | 녹음 중 |

- 펫 단어 소리 5종(§5.4) + 효과음(냠냠·퉤·진화) — Rev A는 직접 녹음/합성한 WAV, 저작권 문제 없는 소스만 (D10).

## 7. 비기능 요구사항

| ID | 항목 | 목표 | 근거/비고 |
|---|---|---|---|
| N1 | 입력→화면 반응 | < 100ms | 미검증 목표. libgpiod 이벤트 기반 |
| N2 | 부팅→펫 화면 | 측정 후 확정 (가목표 40초) | Linux 부팅 시간 미측정 — H0에서 측정 |
| N3 | 상태 저장 | 이벤트 즉시 + 1분 주기, 원자적(tmp→fsync→rename) | 정전 시 손실 최대 1분 |
| N4 | 연속 운용 | 7일 무재시작, RSS 증가 없음 | systemd WatchdogSec |
| N5 | 메모리 | beatling 프로세스 합계 RSS < 150MB | 512MB 중 OS·mpd 여유 확보 (제안값) |
| N6 | SD 쓰기 | < 20MB/일 | 상태 JSON + SQLite 로그 추정치, 실측 확인 |
| N7 | 오프라인 | 네트워크 없이 전 기능 동작 | 이더넷은 개발·업데이트 전용 |
| N8 | 개인정보 | 음성사서함·청취 로그는 기기 밖으로 나가지 않음. QR에는 집계값만 | D6, D7 |

## 8. SW 구성 계획 (구현 지침)

```
mpd ─────────────── 재생 (USB 메모리 = music_directory)
beatling-core ───── 입력(libgpiod) · 펫 엔진 · 청취 판정(mpd idle) · UI(OLED) · 저장
beatling-scan ───── 특징 추출 (aubio), oneshot + 라이브러리 변경 시 트리거
beatling-card ───── QR 카드 정적 웹페이지 (GitHub Pages, D7)
```

**데이터**

| 저장소 | 경로 | 내용 |
|---|---|---|
| 상태 | `/var/lib/beatling/pet.json` | 상태값·단계·형태·식단 누적·last_saved_at |
| 로그 DB | `/var/lib/beatling/beatling.db` (SQLite, WAL) | `tracks`(경로·mtime·길이·BPM·에너지·밝기), `listens`(곡·시작·재생초·판정), `events`(부화·진화·가출 등), `requests`(단어·발생·응답) |
| 녹음 | `/var/lib/beatling/voice/` | Opus 파일 (D6 보관 정책) |
| 설정 | `/etc/beatling/config.yaml` | GPIO 라인·I2C 버스·오디오 장치·경로 |
| 밸런스 | `/etc/beatling/balance.yaml` | §5 수치 전부 |

- 언어: Python 3 + venv (D9). systemd unit 구조는 컨셉 문서 §4 그대로 (Restart=always, WatchdogSec, ProtectSystem=strict).
- 시간 가속 모드: `--time-scale N` 옵션으로 14일 시뮬레이션 (G1, 시험 전용).

## 9. 마일스톤

기간은 주말 작업 기준 추정. HW 단계(H*)는 HW 개발계획서 §7.

| 마일스톤 | 기간 | HW | SW | 게이트 |
|---|---|---|---|---|

| M2 재생+스캔 | 1~2주 | H1 브레드보드 | F-PLAY, F-SCAN | 100곡 스캔, 버튼으로 재생 제어 |
| M3 펫 코어 | 2주 | H2 Rev A 조립 | F-PET, F-FEED, F-SAVE, F-TIME, OLED UI | 시간 가속 3일 시뮬레이션, 정전 시험 통과 |

## 11. 승인 필요 결정 사항

| ID | 결정 | 권장안 | 근거 | 대안 |
|---|---|---|---|---|
| **D1** | Rev A 폼팩터 | **탁상형 상시 전원** | ROCK Pi S의 Linux 부팅·대기전력이 휴대형에 불리 (HW 계획서 R10). 핵심 재미 검증엔 탁상형으로 충분 | 휴대형 → 보드 재선정 필요, 일정 +α |
| **D2** | 음악 소스 | **사용자 로컬 파일만** | 스트리밍 연동은 라이선스·API 제약(추정). 번들 음원은 저작권 처리 필요 | 로열티프리 번들 음원 추가 (V1 결과 보고 Rev B에서) |
| **D3** | 취향 기준 | **절대 기준** (모든 기기 동일 정규화) | "너 펫 뭐 나왔어?" 비교가 성립하려면 기준이 같아야 함 | 내 라이브러리 상대 기준 → 진화 분포는 고르지만 사람 간 비교 무의미 |
| **D4** | 방치 결과 | **가출만, 사망 없음** | 이탈 유발 최소화, 귀환 연출로 재방문 동기 | 사망·리셋 (긴장감↑, 이탈 위험↑) |
| **D5** | 진화 구조 | **5단계, 성체 5종** (§5.3) | 아트 작업량(스프라이트 약 10종)을 Rev A 범위로 제한 | 성체 8종 이상 (아트 비용↑) |
| **D6** | 음성사서함 보관 | **최대 20개, 초과 시 오래된 것부터 삭제, 기기 밖 전송 없음** | SD 용량·개인정보 | 무제한 / USB 내보내기 허용 |
| **D7** | QR 카드 호스팅 | **이 저장소 GitHub Pages (정적 페이지, URL 파라미터만)** | 공개 저장소라 추가 비용 0, 서버 DB 없음 | 별도 도메인 / 카드 없이 화면 표시만 |
| **D8** | 시간 조작 대응 | **역행·과도 점프 시 경과 0 + "어지러움" 연출** | 다마고치식 시계 돌리기를 막되 처벌 대신 연출로 흡수 | 무시(치트 허용) / 페널티 |
| **D9** | SW 언어 | **Python 3** (core·scan), aubio·mpd 활용 | 개발 속도, 기존 라이브러리. A35 성능은 특징 추출을 임포트 시 1회로 제한해 대응 | C (성능↑, 개발 속도↓) |
| **D10** | 아트·사운드 제작 | **미정 — 결정 필요** | 스프라이트 약 10종(128×64 1bit) + 단어 소리 5종 + 효과음. 직접 제작 / 외주 / 생성 도구 중 선택 | — |

**D10은 권장안이 없다.** 비용·일정·저작권에 직접 영향 → 승인 시 지정 필요.
