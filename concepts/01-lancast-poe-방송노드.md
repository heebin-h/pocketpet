# LANCAST — 랜선 하나로 끝나는 PoE 방송 노드

- 작성일: 2026-11-10
- 대상 보드: Radxa ROCK Pi S (RS308-D4: RK3308, 512MB, 무선 없음, 100M Ethernet) — 제품화 시 PoE SKU(`RS308-D4P1…`) 또는 Core SoM
- 상태: 컨셉 (미검증)

## 결론

천장·벽에 붙이는 소형 스피커 노드. **PoE 랜선 하나로 전원+음원**을 받고, 매장·학원·소규모 공장의 정시 방송(종·오픈/마감 안내·BGM·안내 TTS)을 중앙에서 스케줄링한다.

**색: "무선이 없어서 오히려 좋은 방송 장비."** RS308-D4의 약점(무선 없음)을 판매 포인트로 뒤집는다.

---

## 1. 왜 ROCK Pi S여야 하나

| 보드 특성 | 제품에서의 의미 |
|---|---|
| RK3308 = 스마트스피커용 **오디오 SoC** | 원래 목적대로 씀. 오디오 코덱 내장 → DAC 보드 없이 앰프만 (라인출력 핀 위치·품질은 **확인 필요**, P1 측정) |
| **PoE 옵션** (공식 SKU `RS308-D4P1…`) | 전원 공사 불필요 — 천장에 랜선만 |
| **무선 없음** | 와이파이 끊김·BT 페어링·무선 보안 이슈 원천 제거 → 공장·병원·관공서처럼 무선 꺼리는 곳에 강점 |
| 초소형·저사양(512MB) | 스피커 함체 안에 내장. 오디오 재생엔 충분 |
| **Core SoM 버전 존재** ([allnet](https://shop-en.allnet.de/Rock-Pi-S-Core-SOM-512MB-ohne-Wifi-BT/217755)) | 양산 시 SoM + 자체 캐리어(PoE+앰프 일체형)로 이행 경로 있음 |

## 2. 타깃과 셀링 포인트

**1차 타깃: 학원 / 프랜차이즈 매장 / 소규모 공장**

| 고객 | 지금의 불편(추정 — 인터뷰로 검증 필요) | LANCAST |
|---|---|---|
| 학원 | 교시 종을 수동 또는 PC 프로그램 상시 구동 | 스케줄 자동 종, 강의실별 존 방송 |
| 프랜차이즈 | 매장별 BGM·공지 방송 품질 제각각 | **본사가 전 매장 방송을 원격 일괄 관리** (구독 수익 포인트) |
| 소규모 공장 | 휴식·교대 시보 수동/노후 앰프 | 시보 자동화, 유선이라 현장 노이즈·무선 간섭 없음 |

**한 줄 피치:** "블루투스 스피커처럼 끊기지 않고, IP 방송장비처럼 비싸지 않다."

## 3. 장단점

**장점**
1. **설치 단순**: 기존 사무실 랜 + PoE 스위치만 있으면 전기공사 0.
2. **오프라인 내성**: 스케줄·음원을 노드에 로컬 캐시 → 서버/인터넷 죽어도 종·시보는 울린다. (경쟁 클라우드 제품 대비 차별점으로 주장 가능)
3. **동기 재생**: 여러 노드 동시 재생은 오픈소스 [Snapcast](https://github.com/badaix/snapcast)(멀티룸 동기 재생, ARM 지원) 위에 구축 — 바퀴 재발명 안 함.
4. **무선 없음 = 보안 심사 통과 쉬움**: 무선 장비 반입 제한 현장 진입 가능.
5. **원가**: 보드+PoE+앰프로 수만 원대 추정 → 전문 IP 방송장비(SIP 페이징 스피커 등) 대비 큰 가격차 가능. (경쟁 제품 가격 **미확인** — 조사 필요)

**단점 (숨기면 안 되는 것)**
1. **PoE 스위치 없는 곳은 설치 불가** → PoE 인젝터 번들 또는 DC 전원 옵션 필요.
2. **출력 한계**: 802.3af는 수전측 12.95W → 보드 소비 빼면 앰프 몫 대략 8~10W(추정). 소형 공간 전용, 넓은 공장 홀엔 부족 → 802.3at 버전 또는 외부 앰프 출력 모델로 대응.
3. **법정 비상방송설비가 아님**: 화재 비상방송은 소방 인증 대상. "비상방송 대체"로 팔면 안 됨 — 일반 업무 방송으로 포지셔닝 명시.
4. **인증 비용**: 국내 판매 시 KC 전자파 적합성평가 필요(무선 없어서 무선 인증은 빠지지만 EMC 시험 비용·기간은 발생 — 금액 미확인).
5. **공급 리스크**: ROCK Pi S는 출시 오래된 보드 → 단종 리스크. 양산 전 Radxa에 SoM 공급 기간 확인 필수.

## 4. 제품 구성 (MVP)

```
[관리 서버: 소형 PC 또는 클라우드]
   웹 UI: 스케줄 · 존 · 음원 · TTS
   Snapcast server
        │  LAN (PoE 스위치)
   ┌────┼────────┐
 노드A 노드B   노드C   ← ROCK Pi S + PoE HAT + Class-D 앰프 + 스피커
   로컬: 스케줄 캐시 + 음원 캐시 + snapclient + 상태 MQTT
```

- **노드**: Debian, snapclient, 로컬 스케줄러(서버 장애 시 fallback), 상태 보고(MQTT: 온라인 LWT, 마지막 재생, 앰프 온도)
- **서버**: 스케줄 관리, 음원 배포, 다점포 관리(구독형)
- **하드웨어 차별 요소**: 노드 GPIO 접점 입력 1개 → 외부 버튼/기존 설비 접점으로 "즉시 안내방송" 트리거 (비상방송 용도 아님)

## 5. 만들기 전 검증 순서

| 단계 | 할 일 | 통과 기준 |
|---|---|---|
| V1 수요 | 학원장·점주·공장 관리자 각 3~5명 인터뷰: 지금 어떻게 방송하나, 얼마 쓰나 | "돈 내고 바꾸겠다" 응답 절반 이상 |
| V2 경쟁 | 국내 IP 방송장비·학원 종 프로그램·매장 음악 구독 서비스 가격/기능 조사 | 가격 또는 설치 편의에서 확실한 우위 |
| V3 기술 | 보드 1개로 라인출력 품질(노이즈·볼륨), PoE 구동 시 최대 출력·발열, Snapcast 3노드 동기 오차 측정 | 청감상 문제없음, 연속 1주 무중단 |
| V4 비용 | KC 시험 견적, SoM 양산 단가, 함체(금형 vs 3D프린팅) | 목표 소비자가 대비 원가율 확인 |

V1·V2 실패 시 하드웨어는 만들지 않는 게 맞다.
