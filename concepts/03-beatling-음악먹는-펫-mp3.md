# BEATLING (가칭) — 음악을 먹고 자라는 펫 MP3

- 작성일: 2026-11-10
- 대상 보드: Radxa ROCK Pi S (RS308-D4: RK3308, 512MB, 무선 없음, 100M Ethernet) — 프로토타입 기준
- 출발점: ②다이얼 전화 서비스 + ③반려견 말하기 버튼 허브 기능 결합 → MP3 + 다마고치
- 상태: 컨셉 (미검증)

## 결론

**MP3 플레이어 안에 펫이 산다. 펫의 밥은 내가 듣는 음악이다.**
무엇을·얼마나·어떻게 듣느냐에 따라 펫이 배부르고, 삐지고, **취향대로 진화**한다. 조작은 전화 다이얼처럼 번호를 돌려 "펫에게 전화를 건다"(②), 펫은 말하기 버튼처럼 **단어 버튼 소리로 나에게 요구**한다(③).

**색: "내 음악 취향이 키운 생명체."** 연말 음악 결산(Wrapped류)이 1년에 한 번 보여주는 취향을, 매일 자라는 캐릭터로 보여준다.

## 1. 왜 먹힐 수 있나 (가설)

| 흐름 | 연결 |
|---|---|
| Y2K·레트로 기기 회귀 (MP3·디카·다마고치 재유행) | MP3 + 다마고치 = 두 향수를 한 기기에. (Gen Z MP3 회귀 규모는 **미확인** — 기사·검색량으로 확인 필요) |
| 음악 취향 결산 공유 문화 | 펫 진화형 = "내 취향 카드" → 공유 동기 |
| 말하는 강아지 버튼 영상 바이럴 | 펫이 버튼 단어로 요구하는 장면 자체가 숏폼 소재 |
| 스트리밍 피로·"내 파일을 소유" | 로컬 파일 전용을 약점이 아니라 정체성으로 |

⚠️ 전부 유사 트렌드에서 끌어온 가설. 이 제품 자체의 수요 근거는 없음 → 6장 검증.

## 2. 핵심 경험

### 2.1 밥 = 음악 (펫 엔진)
| 듣기 행동 | 펫 반응 |
|---|---|
| 끝까지 들음 | 포만감 +, 기분 + |
| 30초 내 스킵 | "퉤" 애니메이션, 스트레스 + |
| 같은 곡 반복 | 3회까지 "최애 간식", 그 이상 "편식" 경고 |
| 하루 안 들음 | 배고픔 → 버튼 단어로 조름 |
| 3일 방치 | **가출** (사망 없음). 펫의 최애곡을 끝까지 틀면 돌아옴 |
| 밤 늦게 들음 | 펫 졸림 → 다음날 컨디션 ↓ (수면 패턴 풍자) |

### 2.2 취향 진화
- 곡을 라이브러리에 넣을 때 기기에서 오디오 특징 추출: **BPM, 에너지(RMS), 밝기(spectral centroid)** → 곡마다 3차원 "맛" 벡터.
- 펫의 "식단" = 들은 시간 가중 평균 벡터.
- 3일·7일·14일차에 식단 위치로 진화 분기 (예시 — 확정 아님):

| 식단 | 진화형 |
|---|---|
| 고BPM·고에너지 | 불꽃형 (EDM·록·아이돌 댄스) |
| 저BPM·저에너지 | 이불형 (발라드·로파이) |
| 고밝기·중BPM | 반짝형 (팝·시티팝) |
| 저밝기·고에너지 | 그림자형 (힙합·메탈) |
| 고르게 분산 | 잡식 레어형 |

→ "너 펫 뭐 나왔어?"가 대화 소재가 되는 구조.

### 2.3 다이얼 전화 (②에서 가져옴)
다이얼(클릭 있는 로터리 엔코더)을 돌려 번호 입력 → "펫에게 전화":

| 번호 | 서비스 |
|---|---|
| 1 | 펫 상태 (배고픔·기분·식단 그래프) |
| 2 | **펫 추천곡** — 펫이 "먹고 싶은" 맛에 가까운 라이브러리 곡 재생 |
| 3 | 음성사서함 — 펫에게 말 남기기(녹음). 펫이 랜덤 타이밍에 내 목소리를 흉내(피치 변조) |
| 4 | 펫 라디오 — 식단 기반 셔플 |
| 7 | 오늘의 운세 — 펫 기분 + 날짜 시드로 생성 |
| 0 | 비밀번호 — 숨은 번호 발견 시 이스터에그 (커뮤니티 공유용) |

### 2.4 펫의 말하기 버튼 (③에서 가져옴)
- 펫은 단어 버튼 소리(딩 + 녹음된 단어)로 요구: "배고파", "신나는 거", "조용한 거", "놀자", "잘래".
- 사용자는 4개 큰 버튼으로 응답: **밥(곡 주기) / 놀자 / 재워 / 말걸기**.
- 모든 요구·응답 로그 기록 → 주간 **"펫 발언 랭킹"** ("이번 주 '신나는 거' 23회") — ③의 데이터화를 펫에게 적용.

### 2.5 공유 (오프라인)
- 무선 없음 → 화면에 **QR 코드** 표시: 진화형·식단·발언 랭킹을 URL 파라미터로 인코딩 → 폰으로 찍으면 정적 웹페이지가 "취향 카드" 렌더. 서버 DB 없음.
- 128×64 OLED에 QR(25×25 모듈, 2px 스케일 = 50px) 표시 가능 — 폰 인식률은 V3에서 확인.

## 3. 하드웨어 (프로토타입)

```
              ┌─ I2C ─ OLED 128x64 (SSD1306/SH1106)  : 펫 픽셀아트·QR
              ├─ GPIO ─ 로터리 엔코더(클릭) + 푸시     : 다이얼
ROCK Pi S ────┼─ GPIO ─ 큰 버튼 x4 (밥/놀자/재워/말걸기)
 (RK3308)     ├─ 오디오 코덱 출력 ─ 앰프(PAM8302급) ─ 스피커 / 헤드폰 단자
              ├─ 마이크 입력 ─ 음성사서함
              ├─ I2C ─ RTC(DS3231) + 코인셀            : 펫 시간의 기준
              └─ USB host ─ USB 메모리(음악 라이브러리)
```

- GPIO 버튼: 내부 pull-up + SW debounce(20~50ms). 엔코더는 인터럽트(edge) 기반 — libgpiod 이벤트 사용, 폴링 금지.
- 오디오 코덱 출력 핀 위치·품질: **확인 필요** (Radxa 핀맵/product brief). 불만족 시 USB DAC로 대체.
- 마이크 입력 경로(보드 코덱 vs USB 마이크): **확인 필요**.

### ROCK Pi S의 역할 (정직하게)
| 항목 | 판단 |
|---|---|
| 프로토타입 | **적합.** 오디오 SoC + Linux라 특징 추출(aubio, C 라이브러리)·재생(mpd)·녹음을 바로 조립 가능 |
| 양산 탁상형 | 가능. 상시 전원 "펫 스피커" 오브제면 RK3308 유지 |
| 양산 휴대형 | **불리.** Linux 부팅(수십 초 추정)·대기전력·배터리 관리 → 휴대형은 오디오 지원 MCU급 재설계 검토. 결정은 V2 사용 패턴 보고 |

## 4. 소프트웨어 구조

```
mpd (재생)  ◄── beatling-core (Python)
                 ├─ input   : libgpiod 이벤트 (버튼·엔코더)
                 ├─ pet     : 상태머신 (배고픔/기분/졸림/식단벡터/진화단계), 1분 tick
                 ├─ listen  : mpd idle 이벤트로 재생/스킵/완청 판정 → pet에 feed
                 ├─ ui      : OLED 렌더 (픽셀아트 스프라이트, QR)
                 └─ store   : SQLite (청취 로그, 발언 로그) + pet.json
beatling-scan (oneshot) : 새 곡 감지 → aubio로 BPM/RMS/centroid 추출 → SQLite 캐시
```

**설계 원칙**
- **펫 상태 무결성**: pet.json은 tmp 쓰기 → `fsync` → `rename` (원자적 교체). 정전돼도 펫이 깨지지 않음.
- **시간 치트 방지**: 펫 나이는 RTC 기준 + 마지막 저장 시각 비교. 시간 역행 감지 시 경과 0으로 처리하고 로그. (다마고치 시계 돌리기 문화를 "치트 감지 시 펫이 어지러워함" 연출로 흡수하는 것도 가능)
- **특징 추출은 임포트 시 1회**: 재생 중 실시간 분석 안 함 → A35 부하 최소. 곡당 추출 시간은 V3 측정.
- **설정 분리**: `/etc/beatling/config.yaml` (GPIO 라인 번호, 진화 임계값, 다이얼 번호표, 볼륨 한계). 진화 테이블도 데이터 파일로 분리 → 펌웨어 수정 없이 밸런싱.
- **로그**: journald (`journalctl -u beatling-core`).

**systemd unit (core)**
```ini
# /etc/systemd/system/beatling-core.service
[Unit]
Description=BEATLING pet engine
After=mpd.service sound.target
Requires=mpd.service

[Service]
Type=notify
ExecStart=/opt/beatling/venv/bin/python /opt/beatling/core.py --config /etc/beatling/config.yaml
Restart=always
RestartSec=3
StartLimitIntervalSec=300
StartLimitBurst=10
WatchdogSec=30
User=beatling
SupplementaryGroups=gpio audio i2c
ProtectSystem=strict
ReadWritePaths=/var/lib/beatling

[Install]
WantedBy=multi-user.target
```
- `gpio`/`i2c` 그룹명은 배포판 udev 규칙에 따라 다름 → `ls -l /dev/gpiochip* /dev/i2c-*`로 확인 후 설정.
- 메인 루프에서 `sd_notify("WATCHDOG=1")` — UI 루프 hang 시 자동 재시작 (펫 상태는 원자적 저장이라 손실 없음).

## 5. 장단점

**장점**
1. **한 문장 설명**: "음악 먹고 크는 다마고치 MP3." 숏폼 친화.
2. **매일 돌아올 이유**: 배고픔·가출 루프 = 다마고치가 증명한 재방문 장치.
3. **취향 진화 = 공유 동기**: 결과물이 "나"를 드러냄.
4. **②③ 기능이 억지 결합이 아님**: 다이얼 = 펫과의 통화, 말하기 버튼 = 펫의 언어. 세계관이 하나로 묶임.
5. **오프라인 완결**: 계정·앱·서버 없음. QR 공유만으로 바이럴 경로 확보.

**단점 (숨기면 안 되는 것)**
1. **음악 소스 문제 (최대 리스크)**: 대부분 스트리밍으로 듣는데 이 기기는 로컬 파일 전용. 스트리밍 연동은 라이선스·API 제약으로 사실상 불가(추정). → "MP3 회귀층" 또는 "펫 전용 기본 음원 번들(저작권 해결된 인디/로열티프리)"로 타깃을 좁혀야 함.
2. **특징 3개로 취향 구분 한계**: BPM·에너지·밝기만으로는 장르 오분류 많음 → 진화 결과가 "납득 안 됨"이면 재미가 깨짐. V3에서 실제 라이브러리로 분포 확인.
3. **휴대형이면 ROCK Pi S 부적합**: 부팅·전력. 3장 참고.
4. **콘텐츠 소모**: 진화형·애니메이션이 적으면 2주 만에 질림 → 아트·밸런싱이 기술보다 큰 비용.
5. **기존 디지털 펫 경쟁**: 원조 브랜드 신작 등과 비교됨 → "음악이 밥"이라는 축이 겹치지 않는 차별점이어야 함. 명칭·디자인은 기존 캐릭터·상표와 거리 둘 것.

## 7. 구현 순서 (V3 프로토타입)

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| P0 | OS·RTC·OLED·버튼·엔코더·오디오 출력 bring-up | 각 입출력 단독 동작 |
| P1 | mpd 재생 + 다이얼 곡 선택 + 스킵/완청 판정 | 청취 로그 SQLite 기록 |
| P2 | beatling-scan: 특징 추출·캐시 | 라이브러리 100곡 벡터 생성 |
| P3 | 펫 상태머신 + OLED 스프라이트 + 버튼 단어 소리 | 배고픔·기분 변화 육안 확인 |
| P4 | 진화 분기 + 가출/귀환 + 발언 랭킹 | 시간 가속 모드로 14일 시뮬레이션 통과 |
| P5 | 다이얼 서비스(1~7, 0) + 음성사서함 | 번호별 동작 |
| P6 | QR 취향 카드 + 정적 웹페이지 | 폰으로 찍어 카드 표시 |
| P7 | 함체(3D 프린팅) + 7일 연속 사용 | 무중단 7일, 펫 상태 손실 0 |
